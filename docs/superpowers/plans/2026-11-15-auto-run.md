# Auto-run Between Checkpoints Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The designer presses once after evidence input and once at Need approval; every agent run in between starts by itself, in both modes.

**Architecture:** Frontend only. Two pages get a start button that calls an existing run route (`POST /needs/run`, `POST /plos/run`), registers the job with the shared job list, and navigates to the page where the run is followed. Two pages learn to follow one more job kind so the designer waits on a single page per run. No backend, mock-handler or prompt change.

**Tech Stack:** React 19 + TypeScript, react-router-dom 7, axios; the shared job list from `frontend/src/hooks/useProgramJobs` (`useJobs()` → `{ running, latestOf, started, refresh, jobs, programId }`), `startJob(path, body?)` from `frontend/src/api/jobs.ts`, `useReloadOnJobs(kinds, reload)` from `frontend/src/hooks/useReloadOnJobs.ts`, `RunProgress` / `LoadingLine` / `RunFailure` from `frontend/src/components/RunProgress`.

**Spec:** `docs/superpowers/specs/2026-11-15-auto-run-design.md`

## Global Constraints

- Frontend has no unit-test runner. Each task's gate is `npm run build` and `npm run lint` in `frontend/`, both exiting 0, plus the on-screen check in mock mode (`npm run dev:mock`, :5174) that the controller runs after Task 3.
- No change under `src/` (Python), `migrations/`, or `frontend/src/mock/`. The mock already serves `POST /needs/run` (both modes, chains need_combination in multi), `POST /plos/run` with an empty body (chains plo_review in multi), and `GET /evidence/lock`.
- Every auto-run starts from an explicit press; nothing starts on page load or on navigation.
- `POST /plos/run` from the Need page sends **no body** (backend defaults: `run_validation=True`, no note). `POST /needs/run` from the evidence page sends **no body**.
- Before navigating after a start, the page calls `started(job)` from `useJobs()` so the destination page sees the job as running on its first render.
- A refused start (409 / 422) shows the response's Thai `detail` on the page where the button was pressed and does not navigate; a 409 also calls `refresh()`.
- Student/designer-facing strings Thai; code, comments, identifiers English.
- Exact button labels: `ใส่หลักฐานครบแล้ว เริ่มวิเคราะห์` (evidence), `อนุมัติ Need และสร้าง PLO` (Need page). Exact confirm lines: evidence — `เมื่อเริ่มแล้ว หลักฐานจะถูกล็อก แก้ไม่ได้ (ต้องการแก้ให้คัดลอกหลักสูตรแบบหลักฐานอย่างเดียว)`; Need page with stored PLOs — `ชุด PLO เดิมจะถูกแทนที่ด้วยชุดใหม่`; the side link — `ไปหน้า PLO โดยไม่สร้างใหม่`.
- Navigation targets: evidence press → `/need-analysis` (both modes). Need press → `/plo-review` (multi), `/plo-synthesis` (single).
- Commit trailer: `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Run `git branch --show-current` (must print `feat/four-agent-pipeline`) before every commit; stage by explicit path.

## Review Focus

1. **Evidence page when the lock is already closed** (skills or Needs exist, or a job is running): the start button must not render; the existing `NextStageLink` shows instead. Owned by Task 1.
2. **Program switched while a confirm is open** (evidence or Need page): the open confirm closes and its error clears, so a press never starts a run for a program the designer was not looking at when they opened it. Owned by Tasks 1 and 2.
3. **Need page opened with PLOs already stored**: the approve press must not start `/plos/run` without the second press, and the side link navigates without starting anything. Owned by Task 2.
4. **Chained-job gap** (skill_extraction succeeded, need_combination not yet listed; plo_synthesis succeeded, plo_review not yet listed): for one poll the destination page may show its idle state. A press there either starts the same job or gets a 409 — both harmless. Accepted, not engineered around; a reviewer should confirm no *destructive* button (a confirm-free replace) is reachable in that state.
5. **Need page while any job runs** (including skill_extraction arriving from the evidence press): the approve button is disabled, and the page shows the extraction progress, not the "ต้องสกัดทักษะก่อน" empty state. Owned by Task 2.
