Abstract

Project Overview

Curriculum Design Agent เป็น AI agent ที่ช่วยนักออกแบบหลักสูตรอุดมศึกษาไทยผลิตหลักสูตรที่ตรงตาม มาตรฐาน MHESI (กระทรวงอุดมศึกษา วิทยาศาสตร์ วิจัยและนวัตกรรม) และหลักการ Outcome-Based Education (OBE) โดยดำเนินการผ่าน pipeline 5 ขั้นตอนพร้อม Human-in-the-Loop review ณ ทุกจุดเปลี่ยนขั้นตอน Agent หยุดที่ระดับ YLO และส่งต่องาน CLO ให้คณาจารย์ดำเนินการต่อ

"PLO → YLO → CLO. ห่วงโซ่นี้ไม่มีการข้ามขั้น — ทุก outcome ต้องสืบสาวกลับถึง evidence จากผู้มีส่วนได้ส่วนเสีย"

Immutable Rule #1 — CLAUDE.md

ระบบนี้ถูกออกแบบให้ทำงานบน open-source LLM (Typhoon 2 + Qwen 2.5) ผ่าน Ollama เพื่อให้สถาบันการศึกษาสามารถ deploy ได้โดยไม่พึ่งพา paid API ทุก output ผ่านการตรวจสอบ Pydantic validators ก่อนบันทึก — ไม่มีการ hand-parse JSON จาก LLM

5-Stage Pipeline

Pipeline ทำงานตามลำดับโดยไม่ข้ามขั้นตอน Human-in-the-Loop interrupt ทำให้ผู้ออกแบบหลักสูตรสามารถ แก้ไข ปฏิเสธ หรืออนุมัติ output ของแต่ละ stage ก่อนดำเนินต่อ

Intake

▲ HITL CHECKPOINT
→
STAGE 01
Stakeholder Needs
จำแนก evidence จาก employers, alumni, professional councils ด้วย LLM light
▲ HITL CHECKPOINT
→
STAGE 02
Skill Extraction
KeyBERT + BERTopic สกัดทักษะ, จัดกลุ่ม clusters, embed ด้วย BGE-M3
▲ HITL CHECKPOINT
→
STAGE 03
PLO Synthesis
สังเคราะห์ 4–6 PLO จาก skill clusters, ตรวจ SMART + forbidden words
▲ HITL CHECKPOINT
→
STAGE 04
YLO Derivation
อนุมาน YLO matrix ต่อ PLO ทุกตัว Bloom level monotone ตามปี
▲ HITL CHECKPOINT
Input per Stage
  • ProgramMetadata (MHESI fields)
  • Raw stakeholder evidence docs
  • LinkedIn job postings CSV
  • Occupation taxonomy XLSX
Intermediate Artifacts
  • StakeholderEvidence (classified)
  • ExtractedSkill list
  • SkillCluster with demand_score
  • PLO drafts + SMARTCheck
Final Output
  • YLOMatrix (PLO × Year)
  • CHECO export (JSON)
  • มคอ.2 report (Word)
  • Excel Bloom matrix

05

OBE Framework
& Immutable Rules

Outcome-Based Education กำหนดลำดับชั้น PLO → YLO → CLO ที่ไม่สามารถข้ามได้ Agent ทำหน้าที่ถึงระดับ YLO เท่านั้น — CLO เป็นหน้าที่ของคณาจารย์

PLO — Programme Learning Outcome
วิเคราะห์และออกแบบระบบซอฟต์แวร์ขนาดใหญ่โดยประยุกต์ใช้หลักวิศวกรรมซอฟต์แวร์ที่เหมาะสมกับบริบทของอุตสาหกรรมไทยได้อย่างเป็นระบบ
Year 1–4 YLOs
YLO ปีที่ 1 — Bloom: APPLY
ประยุกต์ใช้ design patterns พื้นฐานเพื่อแก้ปัญหาการออกแบบซอฟต์แวร์ในระดับ module ได้อย่างถูกต้อง
YLO ปีที่ 2 — Bloom: ANALYZE
วิเคราะห์ trade-offs ของ architectural patterns และเลือกใช้ได้เหมาะสมกับ requirement ที่กำหนด
YLO ปีที่ 3 — Bloom: EVALUATE
ประเมินคุณภาพของระบบซอฟต์แวร์และเสนอแนวทางการปรับปรุงโดยอ้างอิง quality attributes ที่วัดได้
YLO ปีที่ 4 — Bloom: CREATE
ออกแบบและพัฒนาระบบซอฟต์แวร์ขนาดใหญ่ครบวงจรตั้งแต่ requirements ถึง deployment โดยคำนึงถึง maintainability และ scalability
Faculty → CLO
CLO — Course Learning Outcome (คณาจารย์ออกแบบ)
Agent หยุดที่ YLO — CLO เป็นหน้าที่ของอาจารย์ผู้รับผิดชอบรายวิชา

กฎที่ไม่สามารถแก้ไขได้ Immutable Rules

R1
PLO → YLO → CLO เท่านั้น ห้ามข้าม YLO ไปหา CLO โดยตรง — Agent หยุดที่ YLO
R2
ทุก PLO/YLO ต้องสืบสาวถึง evidence source_cluster_ids และ source_evidence_ids ต้องไม่ว่าง — Pydantic enforce
R3
คำต้องห้ามใน PLO/YLO รู้ จำ เข้าใจ ซาบซึ้ง ตระหนัก ศรัทธา รัก — model_validator ปฏิเสธอัตโนมัติ
R4
หนึ่ง Bloom verb ต่อ outcome อนุญาต 2 verbs เฉพาะเมื่ออยู่ใน adjacent Bloom levels เท่านั้น
R5
Bloom level monotone ข้ามปี YLO ปีหลังต้องมี Bloom level ≥ ปีก่อน ครอบคลุม 3 domains (Cognitive/Affective/Psychomotor)
R6
HITL ทุก stage boundary ไม่มี stage ใดที่ auto-chain ข้ามไปถัดไปโดยไม่ผ่าน human checkpoint approval
R7
Open-source LLM โดย default Paid APIs (Claude, GPT-4o) เป็น config option ไม่ใช่ default — ไม่ hardcode
R8
4–6 PLO เท่านั้น ห้ามสั่ง model ให้สร้าง "เท่าที่ต้องการ" — overlap เพิ่มเมื่อมากกว่า 6
