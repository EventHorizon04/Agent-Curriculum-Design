# Phase-1 lock record (2026-11-15)

> **Superseded** by `2026-11-16-phase1-relock.md`: `validation_max_repairs` 3 → 5 (designer's decision of 2026-11-15), relocked multi 3/3. Kept as the record of what the first lock was.

This is the system the Research Plan ระยะ 1 experiments run on: single-agent and multi-agent modes, both locked at the commit named below. The research plan says every lock must keep the model name and version, the temperature, the prompt files and the code constants. The manifest below the line was generated by `scripts/lock_manifest.py` on a clean tree with `LLM_CACHE_ENABLED=false`, the setting research runs use.

**Evidence the prompts are stable** (`.scratch/reports/2026-11-14-cache-off-lock-runs.md`). A run passes when every job succeeded, there are 6–10 core PLOs, every PLO cites Needs and evidence, and no PLO is `smart_escalated`.

| Mode | Lock-run round | Result |
|---|---|---|
| Multi | round 1, cache off | 3/3 passed |
| Single | round 3, hard core-Need gate and step records | 3/3 passed |

The single runs carry a caveat: the hard gate never fired in a live run.

**Temperature.** By the designer's decision of 2026-11-15, temperature stays as the lock runs used it:

- `temperature=0` in the six calls listed in the manifest.
- Every other call sends none, so it takes the provider default.

**Changes since the lock runs, all inert in research runs.** The HITL send-back work changed some code after the lock runs. None of it alters a run that has no designer send-back and no designer note:

- **PLO send-back:** a per-PLO send-back route and job (`plo_send_back`) that only a designer starts.
- **Review loop:** a guard that skips PLOs marked as sent back. No research run has one.
- **Single needs-task note:** text in `prompts/single_agent.py` that is added only when a designer attaches a note. With no note the opening message is byte-identical, and a test pins it against the pre-change output.
- **Stored shape:**
  - Two nullable PLO columns, `designer_sent_back_at` and `designer_send_back_reason_th` (migration `d9f4a5b6c738`).
  - A single `needs/run` job stores `{"note_th": null}` instead of `{}`.
  - Stored reports and superseded snapshots carry the two null keys.

**Deployment.** Migration `d9f4a5b6c738` must be applied to any database a backend on this code uses.
