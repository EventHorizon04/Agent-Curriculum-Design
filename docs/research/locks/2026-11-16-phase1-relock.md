# Phase-1 relock record (2026-11-16)

This record supersedes `2026-11-15-phase1-lock.md` as the system the Research Plan ระยะ 1 comparison runs on. The manifest below the line was generated by `scripts/lock_manifest.py` on a clean tree with `LLM_CACHE_ENABLED=false`, the setting research runs use.

**What changed.** By the designer's decision of 2026-11-15, `validation_max_repairs` went from 3 to 5 (commit `d5d91b6`). The 28 Oct agreement sets the repair ceiling at 5 for both the SMART check and the PLO review loop, and `plo_review_max_rounds` was already 5. A PLO is now judged at most 6 times instead of 4.

Diffed against the 2026-11-15 manifest, only two lines differ: the commit and `validation_max_repairs`. Everything else is identical, including every prompt sha256, every slot, every token cap and every temperature.

**Multi relock runs.** These ran at `d5d91b6` on the copy DB with the cache off. Each run is an `evidence_only` copy of `program` (the Thai–Chinese translation mock, 14 evidence items), run with no designer action through needs, PLOs and report. The pass criteria are the same as the first lock:
- every job succeeded
- 6–10 core PLOs
- every PLO cites Needs and evidence
- no PLO is `smart_escalated`

| multi-1 | program-run-15 | yes | 11 | 8 (8) | 0 | 1 | 1.97M | 280 (21) | 513 s |
| multi-2 | program-run-16 | yes | 11 | 8 (8) | 0 | 0 | 2.35M | 317 (51) | 993 s |

The relock passed 3 of 3.

Caveat: no PLO in these runs needed more than one repair, so the new ceiling of 5 was never reached. The runs show the change broke nothing. They do not show how the system behaves when a PLO spends four or five repairs. `validation_timeout_seconds` (600, one PLO's whole loop) is unchanged and would bound such a PLO.

**Single mode is unaffected.** No single-mode code path reads `validation_max_repairs`. The single agent judges its own soft criteria in one run, with no vote and no repair loop. Its prompts are byte-identical to the first lock. The single evidence in the 2026-11-15 record therefore still stands: round 3 passed 3 of 3 with the hard core-Need gate.

**Temperature.** Temperature is unchanged from the first lock:
- `temperature=0` in the six calls listed in the manifest.
- Every other call sends none, so it uses the provider default.

**Changes since the first lock, all inert in research runs.** None of these alters a run with no designer action:
- **Auto-run:** the evidence page and the Need-approval page start the existing run routes.
- **Stage bar:** the checkpoint badge and the outline on unreached pages.
- **Documentation edits.**

**Deployment.** Migration `d9f4a5b6c738` is unchanged. Both the shared DB and the copy DB `curriculum_phase1` are at head.
