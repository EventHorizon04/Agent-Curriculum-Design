# 02 — เส้นแบ่ง "ระดับหลักสูตร vs ภารกิจย่อย" ที่เขียนเป็นกฎได้

> แก้ prompt ตัวเดียวกับ ticket 14 และทั้งสองใบพูดถึง "Need ที่ไม่ควรเป็น PLO" คนละเหตุ —
> ใบนี้เพราะ **ระดับผิด** (แคบระดับ CLO) ใบ 14 เพราะ **ฝั่งผิด** (เป็นสิ่งที่สถาบันทำ
> ไม่ใช่สิ่งที่บัณฑิตทำ) อย่ายุบสองเหตุนี้เข้าด้วยกันตอนเขียนกฎ

## Question

กฎทุกข้อใน `summarize_need.py` ดัน **เข้าหา** ความเฉพาะเจาะจง — ต้องมี 3 ส่วน,
ห้ามคำกว้าง, ยาวไม่ต่ำกว่า `MIN_STATEMENT_CHARS` (40), และ (ตั้งแต่ `a8a497b`)
ห้ามลดทอนทักษะเฉพาะทาง + หน้าที่วิชาชีพมาก่อน + job identity test

กฎข้อ 11 ของ guidance (`Curriculum-Level Requirement`) ดัน **ออก**:
❌ `ต้องการผู้ปฏิบัติงานที่แปลสัญญาซื้อขายสินค้า` — ประโยคนี้ผ่าน validator ฝั่งโค้ด
ทุกตัวและตรงกฎเดิมทุกข้อ แต่ guidance บอกว่าแคบเกินระดับหลักสูตร

ทั้งสองแรงมีเหตุผล: Need ที่กว้างเขียน PLO ไม่ได้ · Need ที่แคบเกินกลายเป็น CLO
(ซึ่งอยู่นอก scope ของ agent ตาม immutable rule 1) แต่ prompt ที่บอกทั้ง
"เจาะจงเข้าไว้" และ "อย่าเจาะจงเกิน" โดยไม่มีเส้นแบ่ง จะให้ผลไม่นิ่ง

## ข้อเสนอที่พอทดสอบได้ (ยังไม่ได้ทดสอบ)

> วัตถุของประโยคต้องเป็น **ประเภทของงาน/เอกสาร** ไม่ใช่ **ชิ้นงานเดียว**
> `เอกสารวิชาชีพ` ✅ / `สัญญาซื้อขายสินค้า` ❌

ถ้าเส้นนี้ใช้ได้ มันน่าจะเขียนเป็นกฎใน prompt ได้ตรง ๆ และอาจวัดได้บางส่วนด้วยโค้ด

## สิ่งที่ต้องกดให้แตกก่อนตอบ

1. **มี Need จริงกี่ใบที่แคบเกิน** — วัดจากผลรันที่เก็บไว้แล้ว (Need ของ TCISM)
   ไม่ต้องเรียก LLM ใหม่ ถ้าไม่มีใบไหนแคบเกินเลย กฎนี้แก้ปัญหาที่ยังไม่เกิด
   และการเพิ่มกฎที่ต้านกฎอื่นมีราคาของมัน
2. **ชนกับ `MAX_CORE_PLOS` ยังไง** — เพดาน 10 ทำให้ Need ที่แคบเกินแพงอยู่แล้ว
   (กินสล็อตที่ควรเป็นสมรรถนะระดับหลักสูตร) นั่นเป็นแรงกดที่มีอยู่แล้วหรือไม่พอ
3. **เส้นนี้ขัดกับกฎ "ห้ามลดทอนทักษะเฉพาะทาง" (`a8a497b`) แค่ไหน** — กฎนั้นเพิ่งบอกว่า
   อย่าสรุป `การแปลสัญญา` เป็น `ทักษะการสื่อสาร` ส่วนใบนี้จะบอกว่า `สัญญาซื้อขายสินค้า`
   แคบไป ต้องเขียนให้อยู่ด้วยกันได้ ไม่ใช่สองกฎที่โมเดลต้องเลือกข้าง
4. **บังคับด้วยโค้ดได้ไหม** — `find_vague_phrase` มี precedent ว่ากฎที่วัดได้ควรอยู่ใน code
   แต่ "ชิ้นงานเดียว vs ประเภทงาน" ไม่มีสตริงให้จับ อาจต้องอยู่ใน prompt อย่างเดียว
   ซึ่งแปลว่าต้องมีวิธีวัดผลอื่น

## ผลลัพธ์ที่ต้องได้

เส้นแบ่งที่เขียนเป็นประโยคเดียวได้ + หลักฐานว่าปัญหามีจริงบนข้อมูลที่เก็บไว้แล้ว
หรือคำตอบว่า "ไม่รับกฎ 11" พร้อมเหตุผล

## คำตัดสิน — 2026-09-18: **รับทิศ "ระดับหลักสูตร"** และเขียนเส้นแบ่งลง prompt แล้ว

ถ้อยคำที่ลง (`prompts/summarize_need.py`):

> ประโยคนี้จะใช้สล็อต PLO ของทั้งหลักสูตรไป 1 ข้อจาก 10 ข้อ จึงต้องครอบ 'ประเภทของงาน'
> ที่บัณฑิตทำซ้ำได้หลายสถานการณ์ในสายวิชาชีพนั้น ไม่ใช่ภารกิจย่อยชิ้นเดียวภายในประเภทนั้น
> เช่น 'แปลและตรวจสอบเอกสารสัญญาทางธุรกิจ' อยู่ในระดับหลักสูตร แต่ 'แปลสัญญาซื้อขายสินค้า'
> แคบเกินไป เป็นงานหนึ่งชิ้นในประเภทเดียวกัน
> · ข้อนี้คุมเฉพาะ 'ขอบเขตของวัตถุ' ไม่ได้อนุญาตให้เขียนกว้างลอย ๆ การแก้ประโยคที่แคบเกิน
> คือขยายให้ครอบประเภทของงาน ไม่ใช่ตัดรายละเอียดทิ้ง

### ทำไมเส้นนี้ไม่เถียงกับกฎที่มีอยู่

กฎเดิมทุกข้อคุม **ความเฉพาะเจาะจงของถ้อยคำ** ส่วนข้อนี้คุม **ขอบเขตของวัตถุ** —
คนละแกน ประโยคหนึ่งเป็นได้ทั้งเจาะจงและอยู่ระดับหลักสูตรพร้อมกัน
(`แปลและตรวจสอบเอกสารสัญญาทางธุรกิจ` เป็นทั้งสองอย่าง)

ประโยคสุดท้ายของกฎเป็นตัวกันไม่ให้โมเดลแก้ผิดทาง: โมเดลที่ถูกบอกว่า "แคบเกิน" จะเอื้อม
ไปหา `ทักษะการสื่อสาร` ซึ่งเป็นสิ่งที่กฎ "ห้ามลดทอนทักษะเฉพาะทาง" (`a8a497b`) มีไว้กัน
พอดี — **test `test_the_narrowness_rule_does_not_license_writing_vaguely` ยืนยันว่า
สองกฎนี้ต้องอยู่ด้วยกัน** ถอดข้อไหนออกอีกข้อจะไม่มีคู่ถ่วง

### ผูกกับ `MAX_CORE_PLOS` ไม่ใช่กับความรู้สึก

เหตุผลของเส้นเขียนเป็นตัวเลขที่มีอยู่จริงในระบบ: Need → PLO เป็น 1:1 และหลักสูตรมี
10 สล็อต Need ที่มีค่าน้อยกว่า 1 ใน 10 ของหลักสูตรก็ยังกินสล็อตเต็มใบอยู่ดี
นั่นคือสิ่งที่ทำให้ "แคบเกิน" เป็นปัญหาที่วัดความเสียหายได้ ไม่ใช่รสนิยม

### ⚠️ ครึ่งที่ยังไม่ได้ทำ

ใบนี้ขอ **หลักฐานว่าปัญหามีจริงบนข้อมูลที่เก็บไว้แล้ว** ด้วย — ยังไม่ได้วัด เพราะ Postgres
ไม่ได้รันตอนลงมือ **ยังไม่รู้ว่าผลรัน TCISM มี Need ที่แคบเกินกี่ใบ หรือมีเลยไหม**
สิ่งที่ต้องทำเมื่อ DB กลับมา:

1. ไล่ Need ที่เก็บไว้ ดูว่ามีใบไหนเข้าข่าย "ภารกิจย่อยชิ้นเดียว"
2. ถ้าไม่มีเลย → กฎนี้กันปัญหาที่ยังไม่เกิด ซึ่งยังโอเค แต่ควรบันทึกไว้
3. ถ้ามี → เป็นชุดตัวอย่างสำหรับวัดว่ากฎนี้ได้ผลจริงไหมหลังรันใหม่

Occupational Identity) **ใช้เส้นเดียวกันนี้** แต่ `build_cluster_skills_prompt` อยู่ใน
`_CLUSTERING_CONTRACT` จึงรอลงพร้อมก้อนใหญ่ ไม่ใช่แยกครั้ง — ถ้อยคำที่จะใช้คือเส้นข้างบน
แปลงเป็นระดับกลุ่ม ไม่ใช่เส้นใหม่
