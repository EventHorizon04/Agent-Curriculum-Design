## ผู้ชนะ: T2_field — เพิ่ม `is_graduate_capability` ในสคีมา

recall สูงสุด (56%) false positive เดียว ("การให้บริการวิชาการแก่สังคม" จาก ev09 ชุมชน)
และของทุกอย่างยังอยู่ครบมองเห็นได้ — ตรงกับนโยบายที่ prompt เดิมเขียนไว้แล้วสำหรับ
`is_field_relevant` ว่า *"ห้ามตัดทิ้งเอง ผู้ออกแบบหลักสูตรจะเป็นผู้ตัดสิน"*

ตัวอย่างที่จับได้จาก ev10/ev11: "การบริหารทรัพยากรอย่างคุ้มค่าและยั่งยืน",
"การบริหารจัดการโครงสร้างหลักสูตร", "การวัดและประเมินผลลัพธ์การเรียนรู้",
"การสร้างเครือข่ายความร่วมมือระดับสากล" — ตรงกับสิ่งที่มนุษย์ทิ้งใน `Needs_to_PLO_TCISM.xlsx`

## T1_rule — ตกเพราะ "ตัดทิ้งเงียบ"

กติกาใน system prompt ลดจำนวนทักษะจาก NOISE จาก 9 เหลือ 5 จริง แต่ลด **CORE จาก 29 เหลือ 26**
และ **institutional_direction จาก 20 เหลือ 14** ด้วย โดยไม่มีบันทึกว่าตัดอะไรไป

ปัญหาไม่ใช่ตัวเลข แต่คือ**ตรวจสอบไม่ได้** — ทักษะที่หายไปไม่มีร่องรอย designer ไม่มีทางรู้ว่า
โมเดลตัดสินผิดตรงไหน ซึ่งเป็นเหตุผลเดียวกับที่ prompt เดิมสั่งให้ติดธงแทนตัดทิ้ง

## T3_rewrite — ตกเพราะทำลาย evidence trail

เขียนใหม่ 45 ครั้ง และหลายครั้งเป็นการ**แต่งเติมความเฉพาะเจาะจงที่หลักฐานไม่ได้พูด**:

| ถ้อยคำในหลักฐาน | ชื่อทักษะที่โมเดลเขียนใหม่ |
|---|---|
| "มีความพร้อมในการก้าวสู่เวทีโลก" | การสื่อสารภาษาจีน-ไทยเพื่อการทำงานในระดับสากล |
| "การนำเทคโนโลยีปัญญาประดิษฐ์มาปฏิรูปการศึกษา" | การใช้ปัญญาประดิษฐ์ในงานแปลและล่าม |
| "ผสานเทคโนโลยีปัญญาประดิษฐ์ (AI) เข้าสู่กระบวนการเรียนรู้" | การประยุกต์ใช้ปัญญาประดิษฐ์ในการแปลและการล่าม |

หลักฐานพูดถึงการปฏิรูป**การศึกษา** คำแปลใหม่พูดถึง**งานแปล** — ชื่อทักษะไม่ตรงกับ
`evidence_span_th` ที่ต้องคัดลอกตรงตัวอีกต่อไป ชนกับ immutable rule 2 (ทุก PLO ต้องสาวถึง
หลักฐานได้) และชนกับกติกา verbatim span ใน prompt เดิม

**แต่ข้อสังเกตสำคัญ**: มนุษย์ *ก็เขียนใหม่จริง* — Need 9/10/11 ใน `Needs_to_PLO_TCISM.xlsx`
ถูกเก็บไว้ครบ แค่เปลี่ยนถ้อยคำ. ต่างกันที่ **มนุษย์เขียนใหม่ที่ระดับ Need ไม่ใช่ที่ระดับ
การสกัด** — ตอนนั้นหลักฐานถูกเก็บครบแล้วและ span ยังชี้กลับได้. ในระบบเรา
`summarize_need` คือจุดที่เขียนประโยคอยู่แล้ว → ถ้าจะเขียนใหม่ ต้องไปทำที่นั่น ไม่ใช่ที่นี่

## T4_combo — เจอบั๊กที่ ticket 02 มองไม่เห็น: **scope statement ปนเป็นหลักฐาน**

T4 ให้ NOISE_n เพิ่มจาก 9 เป็น 12 และของที่เพิ่มมาคือ**ข้อความจาก scope statement เอง**
ที่ถูกสกัดออกมาเป็นทักษะ

ตรวจทั้งสองการรัน หาชื่อทักษะที่มีวลีจาก scope statement:

| การรัน | จำนวนทักษะที่ชื่อลอกจาก scope statement | evidence ที่โดน |
|---|---|---|
| T02 `A_none` / `B_broad` / `E_vague` | 0 | — |
| T02 `C_narrow` | 2 | ev05 |
| T02 `D_with_exclusions` | 3 | ev05 |
| **T09 `T4_combo`** | **11** | ev04, ev05, ev11 |

ยืนยันว่าเป็นการแต่ง: `ev04` (148 ตัวอักษร) และ `ev05` (348 ตัวอักษร) **ไม่มีคำว่า
"แปลเอกสาร" / "ล่าม" / "มารยาท" / "ตรวจแก้" อยู่ในข้อความเลย** แต่ผลิตทักษะชื่อ
"การแปลเอกสารธุรกิจและกฎหมายจีน-ไทย", "การล่ามการเจรจาธุรกิจ",
"ความรู้ด้านวัฒนธรรมและมารยาททางธุรกิจจีน" ออกมา — ลอกจาก scope statement คำต่อคำ

**ปนหนักขึ้นเมื่อ evidence สั้นเทียบกับ scope statement** — ev04/ev05 เป็นสอง evidence
ที่สั้นที่สุดในชุด. และปนหนักขึ้นอีกเมื่อ user header ยาวขึ้น (T4 มีทั้ง scope statement
และกติกา field ใหม่)

ผลกระทบ:
1. **`evidence_span_th` ที่ทักษะพวกนี้อ้างต้องเป็นของแต่ง** เพราะข้อความต้นทางไม่มีวลีนั้น
   → ชน immutable rule 2 โดยตรง
2. **ตัวเลขของ ticket 02 มีการปนอยู่เล็กน้อย** (C_narrow 2 จาก 63 ทักษะ) ข้อสรุปว่า
   C_narrow ชนะยังยืน แต่ต้องบันทึกไว้
3. **[ticket 03](../issues/03-extraction-prompt-and-cache.md) ต้องคิดตำแหน่งใหม่** —
   วาง scope statement ไว้ใน user header ติดกับข้อความหลักฐาน คือการเชิญให้โมเดลอ่านมัน
   เป็นหลักฐาน
