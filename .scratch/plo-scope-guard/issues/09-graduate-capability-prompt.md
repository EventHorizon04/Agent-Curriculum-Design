## Question

[ticket 02](02-scope-statement-shape.md) พบว่าอาการที่ใหญ่ที่สุดในหลักสูตรจริงไม่ใช่
"นอกสาขา" แต่คือ **"ไม่ใช่สิ่งที่บัณฑิตทำ"** — ev10 (ผู้บริหาร) กับ ev11 (อ.ผู้รับผิดชอบ
หลักสูตร) ให้ทักษะอย่าง "การบริหารทรัพยากรอย่างคุ้มค่า", "การวัดและประเมินผลลัพธ์การเรียนรู้",
"การรับรองอัตราการได้งานทำ" ซึ่งไม่มีอะไรรอดเข้า PLO ของมนุษย์เลย

ใบนี้ตอบคำถามเดียว: **prompt แบบไหนทำให้โมเดลแยกแกนนี้ได้** — ก่อนจะไปตัดสินว่าจะเก็บ
สัญญาณเป็นอะไร ([ticket 10](10-graduate-axis-signal.md)) เพราะบทเรียนจาก ticket 02
คือการเดารูป prompt ล่วงหน้าผิดได้ (รายการ "ไม่รวมถึง" ทำให้ผลแย่ลง ทั้งที่ ticket 01
สรุปว่าฝั่งลบสำคัญที่สุด)

ทดสอบอย่างน้อย:

1. **เพิ่มกติกาในกติกาเดิม** — บอกใน system prompt ว่าทักษะต้องเป็นสิ่งที่ "บัณฑิตทำได้
   เมื่อสำเร็จการศึกษา" ไม่ใช่สิ่งที่หลักสูตร สถาบัน หรืออาจารย์ทำ
   (ระวัง: แก้ system prompt = `_EXTRACTION_CONTRACT` ขยับ = cache ตายทั้งตาราง —
   ดู [ticket 03](03-extraction-prompt-and-cache.md))
2. **field ใหม่ในสคีมา** — ให้โมเดลตอบ `is_graduate_capability: true|false` แยกจาก
   `is_field_relevant` แทนที่จะกรองเงียบ ๆ (สอดคล้องกับกติกาเดิมของ prompt ที่ห้ามตัดทิ้งเอง
   ให้ติดธงแล้วผู้ออกแบบตัดสิน)
3. **เขียนใหม่แทนติดธง** — สั่งให้โมเดลแปลงประโยคฝั่งสถาบันเป็นฝั่งบัณฑิตถ้าแปลงได้
   ("ต้องการหลักสูตรที่ผสาน AI" → "ใช้ AI ในงานแปลได้") ซึ่งเป็นสิ่งที่มนุษย์ทำจริงใน
   `Needs_to_PLO_TCISM.xlsx` — Need 9/10/11 ถูกเก็บไว้ทั้งหมด แค่ถูกเขียนใหม่

### ทางที่ใช้: **T2 — เพิ่มธง `is_graduate_capability` ในสคีมา**

recall สูงสุด false positive เดียว และของทุกอย่างยังมองเห็นได้ ตรงกับนโยบายที่ prompt เดิม
เขียนไว้แล้วสำหรับ `is_field_relevant` ("ห้ามตัดทิ้งเอง ผู้ออกแบบหลักสูตรจะเป็นผู้ตัดสิน")
สิ่งที่จับได้ตรงกับสิ่งที่มนุษย์ทิ้งจริงใน `Needs_to_PLO_TCISM.xlsx`

### T1 ตก — ตัดทิ้งเงียบ

ลด NOISE 9→5 ก็จริง แต่ลด CORE 29→26 และ institutional 20→14 ด้วย โดยไม่มีร่องรอย
ปัญหาไม่ใช่ตัวเลขแต่คือ**ตรวจสอบไม่ได้**

### T3 ตก — ทำลาย evidence trail

เขียนใหม่ 45 ครั้ง และแต่งเติมความเฉพาะที่หลักฐานไม่ได้พูด: *"การนำ AI มาปฏิรูปการศึกษา"*
→ *"การใช้ปัญญาประดิษฐ์ในงานแปลและล่าม"*. ชื่อทักษะไม่ตรงกับ `evidence_span_th` ที่ต้อง
คัดลอกตรงตัวอีกต่อไป ชน immutable rule 2

**แต่มนุษย์เขียนใหม่จริง** — ต่างกันที่มนุษย์ทำ**ที่ระดับ Need** ตอนที่หลักฐานถูกเก็บครบแล้ว
ไม่ใช่ที่ชั้นสกัดที่ span เป็นตัวร่องรอย → ถ้าจะเขียนใหม่ ที่ทางของมันคือ `summarize_need`

### T4 เปิดบั๊กที่ ticket 02 มองไม่เห็น: **scope statement ถูกอ่านเป็นหลักฐาน**

T4 ผลิตทักษะชื่อลอกจาก scope statement คำต่อคำ 11 รายการบน ev04/ev05/ev11 —
และ `ev04` (148 ตัวอักษร) กับ `ev05` (348) **ไม่มีคำว่า "แปลเอกสาร"/"ล่าม"/"มารยาท"/
"ตรวจแก้" อยู่เลย** แปลว่า `evidence_span_th` ที่มันอ้างต้องเป็นของแต่ง → ชน rule 2 ตรง ๆ

ปนหนักขึ้นเมื่อ evidence สั้นเทียบกับ scope statement และเมื่อ user header ยาวขึ้น
การรันของ ticket 02 ก็มีอาการนี้เบา ๆ (C_narrow 2 จาก 63, D 3 จาก 63) — ข้อสรุปของ 02
ยังยืน แต่ **[ticket 03](03-extraction-prompt-and-cache.md) ต้องคิดตำแหน่งใหม่**:
วาง scope statement ใน user header ติดข้อความหลักฐาน คือการเชิญให้โมเดลอ่านมันเป็นหลักฐาน
