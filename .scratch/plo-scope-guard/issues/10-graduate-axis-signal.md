## Question

รับรูป prompt ที่ [ticket 09](09-graduate-capability-prompt.md) พิสูจน์มาแล้ว
ตัดสินว่าสัญญาณนั้นอยู่ในระบบยังไง — คู่ขนานกับที่ [ticket 04](04-need-level-field-relevance.md)
ทำให้แกน "อยู่ในสาขาไหม"

ต้องตัดสิน:

1. **ตัดที่ระดับ stakeholder ไม่ได้ — ยืนยันและเขียนเหตุผลลง spec**
   เฉลยมนุษย์เก็บ Need ของผู้บริหาร (9 → theme B+D), อ.ผู้รับผิดชอบ (10 → D),
   อ.ผู้สอน (11 → A) ไว้ครบ ตัดเฉพาะ *เนื้อหาบางส่วน* ในสิ่งที่เขาพูด
   → กฎแบบ "`administrator` กับ `program_committee` เป็น evidence ที่ไม่เข้าสู่ PLO"
   ผิดชัดเจน ต้องกันไม่ให้ใครใส่กลับเข้ามาเพราะมันเขียนง่ายกว่า
2. **เก็บบน `ExtractedSkill` เป็นอะไร** — bool คู่ขนานกับ `is_field_relevant` หรือรวมเป็น
   field เดียวหลายค่า? สองแกนไม่ทับกัน ("การสร้างเครือข่ายความร่วมมือระดับสากล"
   in-field แต่ไม่ใช่สมรรถนะบัณฑิต) เลยยุบเป็นค่าเดียวไม่ได้โดยไม่เสียข้อมูล —
   แต่ต้องเขียนเหตุผลไว้ ไม่งั้นคนถัดไปยุบ
3. **รวมขึ้นระดับ Need ยังไง** — ใช้กฎเดียวกับ [ticket 04](04-need-level-field-relevance.md)
   (สมาชิก 1 คนผ่านก็พอ) หรือเข้มกว่า? แกนนี้ต่างตรงที่ทักษะฝั่งสถาบันมักมาเป็นกลุ่มก้อน
   จาก evidence เดียว
4. **`classification` เกี่ยวไหม** — กฎ "requirement wins" ทำให้ทักษะที่วิสัยทัศน์สถาบัน
   พูดถึงเป็น `requirement` เสมอ. วิสัยทัศน์สถาบันคือแหล่งของทั้ง theme D (มนุษย์เก็บ)
   และ "การพัฒนางานวิจัยด้านเศรษฐกิจ" / "การบริหารจัดการและพัฒนาแหล่งรายได้" (มนุษย์ทิ้ง)
   → แกนใหม่ต้องทำงานได้แม้ classification เป็น `requirement` เหมือนกับที่
   `is_field_relevant` ทำ. ยืนยันว่าไม่มีที่ไหนให้ `requirement` ข้ามแกนนี้ไปได้
5. **migration** — คอลัมน์ใหม่บน `extracted_skills` และ (ถ้าข้อ 3 ให้เก็บ) บน `needs`
   ค่า default สำหรับแถวเก่าต้องเป็น "ใช่ เป็นสมรรถนะบัณฑิต" เพื่อรักษาพฤติกรรมเดิม

**ขอบเขต**: ตัดสินใจอย่างเดียว ผลลงเป็นหัวข้อใน spec
