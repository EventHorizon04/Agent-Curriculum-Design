## ปัญหาเชิงออกแบบ: singleton ที่ซ่อมขึ้นมา ปลายทางแยกไม่ออก

`validate_assignments` เขียนไว้ว่า *"skills are never silently dropped"* ซึ่งถูกและต้องคงไว้
แต่ผลลัพธ์คือ **group-of-one ที่โมเดลตั้งใจ กับ group-of-one ที่โค้ดเติมให้ หน้าตาเหมือนกันเป๊ะ**
ตั้งแต่จุดนั้นลงไป มันกลายเป็น Need → PLO → ข้อที่ designer ต้องรีวิวในฐานะความต้องการตลาดจริง
และหาร `demand_score` ของสมรรถนะเดียวออกเป็นหลายส่วน

ร่องรอยเดียวที่มีคือบรรทัด log

## Answer (2026-09-27) — เลือก **ก** ลงแล้ว `e2c1f51` + `b6f0e1d`

`_build_groups` แยกทุก KSEC bucket เป็นสองประชากรตาม `is_graduate_capability` แล้ว cluster แยกกัน
**ไม่ทิ้งอะไร** — ทั้งสองฝั่งกลายเป็น Need ที่สืบกลับหลักฐานได้ `is_in_scope` ยังตัดที่ `plo_synthesis`

เขียนเส้นแบ่งไว้ใน docstring ตามที่ข้อ 2 ของใบนี้เรียกร้อง: กฎ *"never set a skill aside for
looking off-field"* ใน `cluster_skills` พูดถึงแกน `is_field_relevant` ซึ่งนอกสาขา = ความต้องการ
ตลาดที่หลักสูตรไม่ได้คาด = ของจริงที่ต้องอยู่ในสระ · `is_graduate_capability` เป็นคนละแกนและ
แปลว่าไม่ใช่สิ่งที่บัณฑิตทำเลย · **ห้ามยุบสองแกนนี้เข้าหากัน**

ข้อ 3 ตอบว่า **เก็บเป็น Need ตามเดิม** ไม่ใช่ไม่สร้าง — การไม่สร้างคือการลบข้อมูล
