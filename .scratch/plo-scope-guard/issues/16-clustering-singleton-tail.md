## อาการ

บัคเก็ต S ได้ 17-21 กลุ่ม ขณะที่ `allocate_cluster_targets` ขอ **8** · Need ที่มีสมาชิก
ชื่อเดียวจากหลักฐานชิ้นเดียวกองอยู่ที่คะแนนต่ำสุดเท่ากันหมด ทำให้เส้นตัด `MAX_CORE_PLOS`
ตกกลางกลุ่มเสมอกัน 5-8 ใบ และตัดสินด้วย `need_id` ซึ่งเป็น UUID

ไม่ใช่ความยาวรายการ** · การลด `SINGLE_PASS_MAX` ให้ batch จึงแก้ไม่ตรงจุด

## ตัวการคือ 11 แถวที่ extraction แฟล็กถูกแล้วว่าไม่ใช่สมรรถนะบัณฑิต

`is_graduate_capability = False` ทั้ง 11 แถว มาจาก administrator / faculty /
institutional_direction ทั้งหมด และอ่านแล้วถูกทุกใบ:

```
การออกแบบหลักสูตรที่มีความทันสมัยและยืดหยุ่น        [faculty]
การประเมินผลลัพธ์การเรียนรู้                        [faculty]
การยกระดับอัตราการได้งานทำของนักศึกษา              [institutional_direction]  ← ชื่อนี้อยู่ใน K/S ก็ได้ แต่ไม่ใช่สิ่งที่บัณฑิตทำ
การสร้างบัณฑิตที่มีอัตลักษณ์โดดเด่นด้านผู้ประกอบการ  [institutional_direction]
การขยายเครือข่ายความร่วมมือกับมหาวิทยาลัยชั้นนำ     [administrator]
...
```

มันไม่เข้ากับสมรรถนะใดที่ชื่ออื่นประกอบกันเป็น โมเดลจึงวางไม่ลงและปล่อยค้าง แล้วโค้ดซ่อม
เป็น singleton · **แถวพวกนี้ถูก scope guard ตัดทิ้งอยู่แล้ว แต่ตัดที่ `plo_synthesis`
ซึ่งอยู่หลังจากที่มันกินงบ clustering และทำให้กลุ่มรอบข้างแตกไปแล้ว**

## ปัญหาเชิงออกแบบ: singleton ที่ซ่อมขึ้นมา ปลายทางแยกไม่ออก

`validate_assignments` เขียนไว้ว่า *"skills are never silently dropped"* ซึ่งถูกและต้องคงไว้
แต่ผลลัพธ์คือ **group-of-one ที่โมเดลตั้งใจ กับ group-of-one ที่โค้ดเติมให้ หน้าตาเหมือนกันเป๊ะ**
ตั้งแต่จุดนั้นลงไป มันกลายเป็น Need → PLO → ข้อที่ designer ต้องรีวิวในฐานะความต้องการตลาดจริง
และหาร `demand_score` ของสมรรถนะเดียวออกเป็นหลายส่วน

ร่องรอยเดียวที่มีคือบรรทัด log

## ทางเลือก — ยังไม่ตัดสิน

| | ทำอะไร | ได้ | เสีย |
|---|---|---|---|
| **ก** | แยก cluster สองประชากรในบัคเก็ตเดียวกัน (graduate / non-graduate) แล้วเก็บทั้งสองชุด | ไม่ทิ้งอะไร ทุกทักษะยังอยู่กลุ่มเดียว trail ครบ · งบ target คิดจากฝั่ง graduate ซึ่งเป็นฝั่งเดียวที่เป็น PLO ได้ | `is_in_scope` ที่เป็น ratio จะกลายเป็น 1.0/0.0 เสมอ → ชนการตัดสินใจใน [ใบ 11](11-two-axis-selection.md)/[12](12-axis-overlap.md) ต้องเปิดใหม่ |
| **ข** | เรียก cluster รอบสองเฉพาะ index ที่ค้าง แทนที่จะเติม singleton รวด | ตรงจุดที่สุด ถูกที่สุด · ชื่อที่ค้างได้โอกาสจับกลุ่มกันเอง | ไม่แตะต้นเหตุ แค่ให้โอกาสรอบสอง · อาจค้างอีก |
| **ค** | ติดธงว่า singleton ใบไหนมาจากการซ่อม แล้วให้ปลายทางเห็น | ซื่อสัตย์ที่สุด ไม่เปลี่ยนพฤติกรรม | ไม่ลดจำนวน แค่ทำให้รู้ตัว · ลากถึง `_Group` → `Need` → schema |
| **ง** | ลด `SINGLE_PASS_MAX` ให้ batch + merge | ทำให้กฎ merge ที่เขียนไว้ได้ทำงานสักที | **V2 บอกว่าไม่ใช่เรื่องความยาว** — แก้ไม่ตรงจุด |

**ก กับ ข ไม่ขัดกัน** ทำทั้งคู่ได้ · ค เสริมได้กับทุกข้อ

## สิ่งที่ต้องกดให้แตกก่อนเลือก

1. **ตัวเลขข้างบนคือ 3 rep** — ใบ 07 ยังเปิดอยู่ ยังไม่มีฐาน variance ที่ตกลงกันไว้
   V0 เองกว้าง 11-19 · ที่เชื่อได้คือ **V1 vs V2 ที่ความยาวเท่ากัน** ไม่ใช่ค่าเฉลี่ยเดี่ยว ๆ
2. **ทางเลือก ก ชนกฎที่เขียนไว้ใน prompt เอง** — `cluster_skills.py` บอกว่า *"never drop,
   exclude, or set aside a skill for looking off-field"* · กฎนั้นพูดถึงแกน `is_field_relevant`
   (นอกสาขา = ความต้องการตลาดที่หลักสูตรไม่ได้คาด = ของจริง) ซึ่ง**คนละแกน**กับ
   `is_graduate_capability` (ไม่ใช่สิ่งที่บัณฑิตทำเลย) — แต่ต้องเขียนเส้นแบ่งนี้ให้ชัดก่อนลงมือ
   ไม่งั้นครั้งหน้าจะอ่านว่าขัดกัน
3. **ถ้าเลือก ก ต้องตอบด้วยว่ากลุ่มฝั่ง institutional เก็บไว้ทำอะไร** — เก็บเป็น Need ที่
   `is_in_scope` ตัดทิ้งเหมือนเดิม หรือไม่ต้องสร้าง Need เลย · ข้อหลังคือการลบข้อมูล ต้องตั้งใจ
