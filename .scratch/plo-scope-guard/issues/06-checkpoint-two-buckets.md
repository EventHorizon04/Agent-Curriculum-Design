# 06 — checkpoint กับ report โชว์ Need ที่ถูกกันยังไง

Map: [PLO synthesis ที่ไม่หลุด scope ของหลักสูตร](../map.md)
Type: prototype
Status: open
Blocked by: 05 (resolved), 11 (resolved)

## Question

ตกลงแล้วว่าแยกสองก้อน: **"แพ้ demand"** กับ **"นอกขอบเขตหลักสูตร"** เพราะ designer
ต้องทำคนละอย่าง — แพ้ demand คือยอมรับได้ ไม่ต้องทำอะไร; นอกขอบเขตคือต้องอ่านว่า model
ตัดสินสาขาถูกไหม ถ้าผิดแปลว่า scope statement เขียนไม่ดี

ทำ prototype ของหน้าที่ designer เห็นจริง เพื่อตอบ:

- แต่ละรายการในก้อน "นอกขอบเขต" ต้องแสดงอะไรถึงจะตัดสินได้ในไม่กี่วินาที — statement ของ Need,
  ชื่อ skill สมาชิก, สัดส่วน in-field, evidence span, demand_score ที่จะได้ถ้าไม่ถูกกัน?
- ถ้า designer อ่านแล้วเห็นว่าผิด ทางไปต่อคืออะไร — ข้อความบอกว่า "แก้ scope statement
  แล้ว re-run skill extraction" จะเขียนยังไงให้ไม่กำกวมว่าต้องรันอะไรใหม่บ้าง
  (ตกลงไว้ว่าระบบเตือนอย่างเดียว ไม่ re-run ให้เอง เพราะจะชน immutable rule 7)
- อยู่ที่ไหน: หน้า checkpoint ของ plo_synthesis, `plo_report`, หรือทั้งสอง
- `plo_report` ตอนนี้บอกชื่อ Need ที่ไม่ถูกใช้อยู่แล้ว — ต่อยอดหรือทำใหม่

หลังทำเสร็จ เช็กว่าคำตอบทำให้ fog ข้อ "PLO report / มคอ.2 exporter ต้องรายงานไหม"
บนแผนที่ ชัดพอจะแตกเป็น ticket หรือยัง

**ผลลัพธ์**: mockup + คำตอบว่าโชว์ที่ไหน แสดงอะไร ลิงก์ไว้จาก ticket นี้
