## Question

ตกลงแล้วว่า scope statement เป็น **free text, optional** เก็บตอน intake และไม่มีค่า =
พฤติกรรมเดิมเป๊ะ. ที่ยังไม่รู้คือ **designer พิมพ์อะไรออกมาจริง** และข้อความแบบไหนทำให้
extraction model ตัดสิน `is_field_relevant` ได้ต่างจากเดิม

ทำ prototype เพื่อตอบ:

- ข้อความ 3-4 แบบ (กว้าง / แคบ / มีข้อยกเว้น / เขียนแย่) ป้อนเข้า `build_extract_skills_prompt`
  กับ evidence จริงจาก `Data/linkedin_offers2026-04-30.csv` แล้วดูว่าธง `is_field_relevant`
  ขยับจริงไหม และขยับตรงทางไหม
- ต้องมี placeholder / helper text อะไรในฟอร์ม intake ถึงจะได้ข้อความแบบที่ใช้ได้
- ผลจาก ticket 01: ควรมีของตั้งต้นให้แก้ (จาก ISCED-F / มคอ.1) หรือกระดาษเปล่าดีกว่า
- ความยาวเท่าไรถึงพอ — สั้นไปไม่ต่างจาก `field`, ยาวไปกินโควตา token ทุก window ของทุก evidence

**ผลลัพธ์**: ตัวอย่างข้อความที่ยืนยันแล้วว่าใช้ได้ + copy ของฟอร์ม + คำตอบว่ามีของตั้งต้นไหม
ไม่ต้อง merge อะไร — prototype ทิ้งได้ ลิงก์ไว้จาก ticket นี้พอ

## เพิ่มหลัง ticket 01 ปิด

[ticket 01](01-scope-boundary-standards.md) เปลี่ยนโจทย์ของใบนี้สามอย่าง — อ่านก่อนเริ่ม:

1. **หลักฐานชี้ไปที่สองช่อง ไม่ใช่ free text ช่องเดียว** — ISCED-F เพาะฝั่ง "ครอบคลุม" ได้
   แต่ฝั่ง "ไม่รวมถึง" **ไม่มีมาตรฐานไหนเพาะให้ได้เป็นภาษาไทยเลย** (มคอ.1 เขียนศูนย์ครั้ง,
   AUN-QA ไม่มี, ISCED-F มีแต่เป็นอังกฤษและชี้ด้วยรหัส) ซึ่งเป็นฝั่งที่ map บอกว่าเป็นหัวใจ
   → **ขัดกับที่ตกลงตอนวาง map ว่า free text ช่องเดียว** ใบนี้ต้องเปิดคำถามนั้นใหม่
   ไม่ใช่ทำตามมติเดิมเงียบ ๆ
2. **ถ้าเลือกทาง ISCED-F seed = ตัดสินสามเรื่องพร้อมกัน** — intake ต้องถาม `isced_code`
   4 หลัก (ตอนนี้ไม่ถาม, และ 2-3 หลักใช้ไม่ได้เพราะเป็นหัวข้อเปล่า), `data/isced.py`
   ต้อง import description เพิ่ม, และต้องแปลไทย. ถ้าราคานี้แพงไป คำตอบอาจกลับไปเป็น
   กระดาษเปล่า + few-shot ในฟอร์ม
3. **ห้ามอ้าง AUN-QA** — keyword sweep ยืนยันไม่มีข้อความรองรับ

## เพิ่มหลัง ticket 08 ปิด

[ticket 08](08-fetch-post-2565-standards.md) อ่านตัวบทจริงแล้ว — **ไม่มีหัวข้อ "ลักษณะของสาขา"**
ในชุดหลัง 2565 และ **ฝั่งลบยังเป็นศูนย์** เหมือน มคอ.1 แต่เจอของที่ใช้แทนได้:
หัวข้อ **"๑. ด้านความรู้"** แจกแจงองค์ความรู้ในสาขาเป็นภาษาไทย พร้อมบล็อก "คำอธิบาย:"
ที่นิยามศัพท์ — เป็น seed ฝั่งบวกที่ดีกว่า ISCED-F สามทาง (ภาษาไทย, ยังบังคับใช้,
อ้างใน มคอ.2 ได้)

ทำให้ข้อ 2 ข้างบนกลายเป็น **การเลือกระหว่างสอง seed ที่ครอบคนละส่วน** ไม่ใช่ ISCED-F เดี่ยว ๆ:

| | ครอบคลุมสาขา | ภาษา | สถานะทางกฎหมาย | ต้องมีอะไรก่อนใช้ |
|---|---|---|---|---|
| ISCED-F detailed | ทุกสาขา | อังกฤษ | ไม่ผูกพันไทย | รหัส 4 หลักที่ intake + import description + แปล |
| ประกาศ กมอ. หลัง 2565 | **เฉพาะสาขาที่มีสภาวิชาชีพ** | ไทย | บังคับใช้ | หาตัวบทรายสาขา + parse |

หลักสูตรส่วนใหญ่ (บริหารธุรกิจ, วิศวกรรมทั่วไป, มนุษยศาสตร์, วิทยาการคอมพิวเตอร์)
ไม่มีประกาศ กมอ. เลย → ถ้าเลือกทางนี้ทางเดียว seed จะว่างสำหรับโปรแกรมส่วนใหญ่

**และไม่ว่าเลือกทางไหน ฝั่ง "ไม่รวมถึง" ก็ยังต้องให้ designer เขียนเองอยู่ดี** —
สามแหล่ง (ISCED-F ไทย / มคอ.1 / ประกาศชุดใหม่) ให้ศูนย์ทั้งหมด ยกเว้น ISCED-F ฉบับอังกฤษ

**ของแถมจาก 08**: 4 ด้านของประกาศตรงกับ KSEC หนึ่งต่อหนึ่ง (ความรู้=K, ทักษะ=S,
จริยธรรม=E, ลักษณะบุคคล=C) — ใช้อ้างใน spec ได้ว่า `SKILL_KSEC` สอดคล้องกฎหมายปัจจุบัน

## Answer

ผลเต็ม: [`../research/02-prototype-findings.md`](../research/02-prototype-findings.md)
ทดสอบบนหลักสูตรการแปลจีน-ไทย TCISM ด้วย evidence จริง 14 รายการ เทียบกับเฉลยของมนุษย์
(`Data/Needs_to_PLO_TCISM.xlsx`) — 5 variant × 14 item บน `gemma4:31b-cloud` (ollama cloud),
70/70 สำเร็จ

### รูปของ scope statement: **free text ช่องเดียว ฝั่งบวกล้วน แจกแจงเป็นรายการ**

ยืนตามมติเดิมของ map (ช่องเดียว) และ **กลับข้อเสนอของ ticket 01** ที่ว่าควรแยกช่อง "ไม่รวมถึง"
— หลักฐานบอกตรงข้าม:

| variant | true positive (NOISE) | false positive (CORE) |
|---|---|---|
| A_none (control) | 3/9 (33%) | 0/29 |
| B_broad | 2/8 (25%) | 0/29 |
| **C_narrow** | **4/8 (50%)** | 0/27 |
| D_with_exclusions | **0/8 (0%)** | **1**/27 |
| E_vague | 2/8 (25%) | 0/27 |

- **รายการ "ไม่รวมถึง" ทำให้แย่ลง** — D เขียนไว้ตรง ๆ ว่ากันงานบริหารสถาบัน แล้วได้ศูนย์
  แย่กว่าไม่ใส่อะไรเลย และเป็นตัวเดียวที่ทำ false positive. มันจับเฉพาะของที่อยู่ในรายการเป๊ะ ๆ
  (7 ตัวในกลุ่มอื่น) — รายการ exclusion ดึงความสนใจโมเดลไปอยู่กับรายการ แล้วปิดวิจารณญาณกับอย่างอื่น
- **กว้างหรือลอย ๆ แย่กว่าไม่มี** — B (25%) และ E (25%) ต่ำกว่า control (33%) ทั้งคู่
- เฉพาะ **แคบ + แจกแจง + ฝั่งบวก** ที่ดีกว่า control อย่างมีความหมาย

### ของตั้งต้นในฟอร์ม: **มี และรูปที่ต้องเพาะคือรูปของ C_narrow**

C_narrow คือ "ครอบคลุม X, Y, Z, และ W" ยาวราว 150 ตัวอักษร ซึ่งเป็นรูปเดียวกับที่
[ticket 01](01-scope-boundary-standards.md) พบว่า ISCED-F `Inclusions` และ
[ticket 08](08-fetch-post-2565-standards.md) พบว่าประกาศ กมอ. หัวข้อ "๑. ด้านความรู้" เขียนไว้
— ทั้งสองแหล่งให้ฝั่งบวกแบบแจกแจงพอดี **และฝั่งลบที่หาไม่ได้จากที่ไหนเลย กลายเป็นเรื่องดี
ไม่ใช่ช่องว่าง** ไม่ต้องหาแล้ว

ความยาว: B_broad (~90 ตัวอักษร บรรยายรวม ๆ) ไม่พอ, C_narrow (~150 ตัวอักษร แจกแจง 4 รายการ)
พอ → floor ควรอยู่ที่การแจกแจงได้อย่างน้อย 3-4 รายการ ไม่ใช่จำนวนตัวอักษรล้วน

### เพดานของแกนนี้: จับได้ครึ่งเดียว

variant ที่ดีที่สุดได้ 50% และธง OFF ไม่เคยเกิน ~10% ของทักษะทั้งหมด — scope statement
ช่วยได้จริงแต่ไม่พอจะเป็น guard เดี่ยว ๆ ข้อนี้ทำให้ [ticket 07](07-eval-protocol.md)
ต้องตั้งเกณฑ์ผ่านจากฐานนี้ ไม่ใช่จากความคาดหวัง

### สิ่งที่ prototype นี้เปิดออกมาและใหญ่กว่าคำถามของใบนี้

เฉลยมนุษย์มี **PLO4 = theme D "ผู้ประกอบการ/นวัตกรรม และความพร้อมสู่สากล"** แปลว่า
"ผู้ประกอบการ" และ "การตลาดดิจิทัล" ที่ดูหลุดสาขาสำหรับหลักสูตรการแปล **อยู่ในขอบเขตจริง**

สิ่งเดียวที่มนุษย์ทิ้งคือเนื้อหาบริหารสถาบัน — "ดึงดูดนักศึกษา", "บริหารทรัพยากรอย่างคุ้มค่า",
"วัดผลลัพธ์การเรียนรู้ได้ชัดเจน", "รับรองอัตราการได้งานทำ" — แต่มนุษย์ **ไม่ได้ทิ้งทั้ง
stakeholder**: Need ของผู้บริหาร (9) ไปเป็น theme B+D, ของ อ.ผู้รับผิดชอบ (10) ไป D,
ของ อ.ผู้สอน (11) ไป A. ที่ถูกตัดคือ *เนื้อหาบางส่วนในสิ่งที่เขาพูด* ไม่ใช่ตัวเขา

→ **มีแกนที่สอง: "บัณฑิตทำได้หรือไม่"** ซึ่งไม่ทับกับ "อยู่ในสาขาหรือไม่"
("การสร้างเครือข่ายความร่วมมือระดับสากล" อยู่ในสาขาวิทยาลัยนานาชาติเต็ม ๆ แต่ไม่ใช่สิ่งที่
บัณฑิตคนหนึ่งทำ) และตัดที่ระดับ stakeholder ไม่ได้ ต้องตัดที่ระดับทักษะ
